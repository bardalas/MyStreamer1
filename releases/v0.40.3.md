## Playback and source-search fixes

- Continue Watching resumes the exact saved film/episode, even if metadata is unavailable or incomplete. The player label follows that episode; existing progress data and resume seeking are preserved.
- Repeated Resume presses start only one lookup/playback. Navigation and same-route redraws invalidate old requests, so delayed answers cannot start playback, redirect the user, or clear a newer loading state. Lookup errors allow retry.
- Kan, Mako/Keshet and Reshet program links are checked independently of installed streaming add-ons. Results arrive progressively, failures remain visible, and stalled provider operations have deadlines. A program page is never treated as a direct playable stream.
- Autoplay does not wait for broadcaster directory searches. Stale results cannot overwrite another title's source list or availability cache.
- The Continue Watching progress bar now uses one fill element with a finite, clamped percentage instead of showing a full background at partial progress.

## Release engineering

- Version: 0.40.3 (Android versionCode 4003). Application ID and release-signing configuration are unchanged.
- Dependency-free JavaScript regressions run before every APK build and on pull requests. Existing tag-based releases remain supported; an explicit `release: vX.Y.Z` commit on main can also publish after successful validation/build.
- The release workflow creates any missing tag at the exact tested build commit. Ordinary main commits still upload test artifacts only.

## Validation scope

The automated suite exercises real application modules using mocked provider responses, a minimal DOM contract, fake timers, and the Android playback bridge. It is not a physical Android TV/phone test or a visual RTL/layout acceptance test. Those device checks remain required.
